# etkn-monitor —— ETKN 监控（v2.4）

手机友好的 ETKN（ETK vNext）监控面板：队列规模、入库进度、完成速率与 ETA、分类任务统计、手动链路测速、失败任务重试、手动整理触发、异常媒体明细。

**v2.4 变化**（2026-09-16）：
- **排优枚举结论**：ETKN 无原生任务优先级/排优接口（openapi 全量扫描：唯一 promote=共享池虚拟导入；TaskRunRequest 仅 parameters；priority 仅存在于追剧订阅模型）——按指令放弃，不做二创
- **类型翻译**：subscription_metadata→订阅元数据 等 KIND_ZH 映射，未知类型回退原名
- **拥堵可视化**：分类队列「排 X」≥150 标红；入库页顶部「⚠ XX积压 N，预计拖慢整理」提示行（低于阈值/为 0 隐藏）

**v2.3.3 变化**（2026-09-16）——响应式布局美化（功能零改动）：
- 断点：≥900px 桌面（1200px 居中、统计卡 4 列）/ ≤480px 手机（统计卡 2×2、数字加大）
- 手动操作：手机 2×2 等宽网格，桌面横排；顺序=手动整理/生成封面/开始测速/更多任务
- 页头：手机两行（标题+版本 / 更新于+状态色点徽章）；桌面单行
- 任务统计表：手机合并列（任务/项、成功/异常），桌面 5 列；标题列省略号+悬浮全称
- 测速状态配色：正常绿、异常红（替代原橙色）

**v2.3.2 变化**（2026-09-16）：
- **手动操作区扩展**：新增「生成媒体库封面」按钮（task_key=generate-virtual-library-covers，Pro 任务，本机 is_pro=true 已验证；`{"parameters":{}}` 最小载荷走服务端默认），两页签同位并排=手动整理/生成封面/开始测速+「更多任务 →」跳 ETKN 任务中心；确认弹窗文案「按封面生成配置批量更新媒体库封面（全库批量）」；成功 toast「已提交进入队列」；独立忙锁防连点
- **主题记忆**：键改 `etkn_monitor_theme`（兼容迁移旧键 etknmon_theme）；head 内联脚本渲染前读主题防闪烁；未设置默认深色
- **测速表格化**：每域名一行=域名(状态色点)/TCP建连/TLS握手/总耗时/状态；失败红行+错误原样；404/301/302 黄色「可达」；≤480px 折两行（域名+状态 / 三项耗时）；表头上方「测于 HH:MM」
- 502 专项结案：ETKN 重启计数 0、近 3 小时 5xx=0、三链路全 200——维持「瞬时链路抖动已自愈」结论，非本服务与 ETKN 故障

**v2.3.1 变化**（滞后修复，2026-09-16）：
- **根因**：单线程串行采集——诊断汇总固定 ~13s + succeeded 深翻页（当日千条时 15 页 ~97s），单轮 110s+，快照滞后 2-3 分钟（实测复现 09:49→09:52）
- **修复**：拆双速双快照。快线程只拉 running+queued（与 ETKN 任务中心 UI 同源同参，<1s）默认 **2 秒**一轮；慢线程负责深翻页/诊断/records，默认 120 秒一轮；两线程独立互不阻塞
- succeeded 深翻页改为「整页早于今日 0 点即停」（口径不变，从翻到底改为翻到今日边界）
- 「更新于」= 快快照时间；与慢快照偏差 ≥1 分钟时显示「统计截至 hh:mm（滞后 N 分）」，滞后可见
- 任务创建到 monitor 可见 ≤ 快轮询间隔+单请求耗时（实测 ~3 秒），远优于 60 秒目标

**v2.3 变化**（相对 v2.2）：
- **「更新于」时间源修正**：改为浏览器本地最近一次成功取数时刻（后端快照时间在轮询间隔内会天然滞后），加 `cache:'no-store'` 与 `visibilitychange` 回前台立即刷新，偏差 ≤ 轮询间隔且无后台节流滞留

- 502 排查结论（08:48 事件）：ETKN 容器/DB 自 00:41 持续运行零重启、日志零 5xx、三条链路（直连/Lucky/公网 CDN）复测全 200——瞬时链路抖动已自愈，与 v2.2 部署无关；08:01~08:07 追剧刷新连败为 TMDB 同步状态与共享中心分片缺陷（已知上游问题），与 502 不同源

**v2.1 变化**（相对 v2）：
- **重试按钮收敛**：仅「刮削入库」类（workflow_type=batch_ingest）显示重试按钮，其余类型不显示（ETKN 官方白名单仅刮削类，其余必 409）；按 workflow_type 过滤，不硬编码标题；列表标题去「（可重试）」
- **手动整理网盘文件**：任务统计页一键触发，原样转发 ETKN 原生接口 `POST /api/task-center/tasks/organize-p115/runs`（参数形态取自历史运行），确认弹窗→成功 toast→自动刷新；复用 mGo 忙锁防连点
- **异常媒体明细**：入库页「异常（媒体）」数字可点击，弹出当日明细（文件名+原因+时间），数据源 `GET /api/p115/records?status=unrecognized|failed`，无数据显示空态，不硬造数据

**v2 变化**（相对 v1）：
- 新增**手动链路测速**（仅按钮触发、无定时）：对 image.tmdb.org / api.themoviedb.org / api.telegram.org / shared.55565576.xyz 发起普通请求——不设代理、不强制直连，流量自然走软路由当前策略；每域名输出 TCP 建连 / TLS 握手 / HTTP 总耗时与状态，超时 10 秒。
- 任务统计页失败列表每行新增**重试按钮**：确认弹窗 → 调用 ETKN 官方重试接口（`POST /api/workflows/{id}/retry-failed`）→ 成功后任务自动进 ETKN 队列并刷新；ETKN 返回 409 等拒绝时**原样展示**其错误信息，不隐藏不绕过。
- 两页口径统一：完成/异常媒体全站以 p115 记录为准；分类表「任务项」列为运行条目数（含重试重算），仅作任务维度参考。

**v1 特性保留**：
- 入库进度页：待处理（当前活跃队列，未终态、当日创建）、今日完成、异常、ETA（滚动窗口速率外推，默认 10 分钟可配；速率为 0 显示「计算中」防除零）、分类队列。
- 卡片口径：媒体数主口径（p115 记录），任务数副标（如「356媒体·41任务」），每卡标注单位。
- 轮询间隔默认 15 秒（可配）；前端显示「更新于 XX:XX」。
- 登录会话存内存、401 自动重登。
- v1 的清空/一键排优按钮仍不提供（v2 亦未加）。

## 部署（飞牛 fnOS）

```bash
# 1. 克隆（或复制）项目
cd /vol1/1000/docker
git clone https://github.com/YisBoss/etkn-monitor.git
cd etkn-monitor

# 2. 创建 .env（密码自填，绝不入仓）
cat > .env <<'EOF'
ETKN_BASE_URL=http://192.168.1.22:5257
ETKN_USERNAME=YisBoss
ETKN_PASSWORD=你的ETKN密码
MONITOR_PORT=8620
POLL_INTERVAL=15
EOF
chmod 600 .env

# 3. 启动
docker compose up -d

# 4. 验证
curl http://127.0.0.1:8620/api/meta
```

浏览器访问 `http://<NAS-IP>:8620`。

## 配置

| 变量 | 说明 | 默认 |
|---|---|---|
| ETKN_BASE_URL | ETKN 地址 | http://192.168.1.22:5257 |
| ETKN_USERNAME | 登录用户名 | YisBoss |
| ETKN_PASSWORD | 登录密码（必填） | 无 |
| ETKN_ETA_WINDOW | ETA 滚动窗口（分钟） | 10 |
| POLL_INTERVAL | 轮询间隔（秒） | 15 |
| MONITOR_PORT | 监听端口 | 8620 |

## 安全

- 零密钥设计：密码只放 `.env`（600 权限），不入代码、不入仓库；Git 已忽略 `.env`。
- 测速与重试均为手动触发，无任何定时任务。
- 重试仅转发 ETKN 官方接口；ETKN 的拒绝（409 等）原样透传展示。

## 接口

| 端点 | 方法 | 说明 |
|---|---|---|
| `/` | GET | 前端页面 |
| `/api/meta` | GET | 版本与配置 |
| `/api/status` | GET | 监控快照（轮询缓存） |
| `/api/speedtest` | POST | 手动测速（4 域名，无代理自然路由） |
| `/api/retry/{id}` | POST | 转发 ETKN retry-failed，透传状态与错误 |
