# etkn-monitor —— ETKN 监控（v2.9.13）

手机友好的 ETKN（ETK vNext）监控面板：队列规模、入库进度、完成速率与 ETA、分类任务统计、手动链路测速、失败任务重试、手动整理触发、异常媒体明细。

**v2.9.13 变化**（2026-09-27）——告警改用 `news` 卡片，微信端也有「可点名字」：

- **有标题或有链接的短消息，一律发 `news`（图文消息）**：第一条 = 标题 + 正文 + 推送时间，
  **每个链接各占一条「可点名字」**。这样微信端和企业微信端的观感就一致了
  ——都是「一张卡片 + 一行行可点名字」，而不是微信端显示一长串原始网址。
  （`textcard` 只能带**一个** URL，`text` 又不渲染 markdown 链接，只有 `news` 能带多个。）
- 正文超过 512 字节（`news` 第一条 description 的上限）时，仍回落 `text`（2048 字节）。
  回落时**先给「链接行 + 推送时间」留位、再从正文里裁**——旧写法把「正文 + 链接行」当一整块裁，
  正文一长链接行就被截没了，而链接恰恰是这条消息唯一能操作的东西。
- 「测试企业微信」自检也补上按钮，走和真实告警同一条卡片路径，便于直接验证观感。
- 版本串 v2.9.12 → v2.9.13（`/api/meta` 与启动横幅）。

  这种（不含「告警」二字，实际踩到：整理清空提醒仍然显示两行标题）。

  覆盖全部四种真实调用形态（告警 / 整理清空 / 测试推送 / 企微自检），并且**标题图标与正文图标
  不一致时也成立**（测试推送就是 `✅ 测试推送` 配 `⚠️ ETKN 告警 · 测试推送`）。
- 加了「不该误删」的反向用例：正文首行与标题无关时原样保留。

**v2.9.10 变化**（2026-09-27）——任务中心按工具箱 5 大类展开 + 修 markdown 泄漏与测速误报：

- **企微菜单「任务中心」改成 ETKN 工具箱的 5 个分类**（`🎬媒体维护` / `📁115整理` /
  `📺订阅追剧` / `📚媒体库` / `🔑账号系统`）。企微自定义菜单**只有两级**（一级最多 3 个、
  每个一级下最多 5 个二级，没有第三级），所以「点分类再展开子任务」菜单本身做不到——
  改成**点分类 → 服务端推一条图文消息（`news`）**，每条 = 该分类下一个子任务，
  **点条目 → 确认页 → 确认执行 → 触发 ETKN**。
- **子任务链接指向确认页而不是直接触发**：微信/企微打开链接会预取，点开即跑等于
  打开一条消息就把整类任务全触发。确认页是 GET（预取只看到按钮），执行走 POST + 进程令牌。
- **每类只收业务主链路 + 非破坏性任务**（共 26 个）：排除 `delete-115-shares`（删除分享入库）、
  `execute-duplicate-media`（执行去重）、`apply-auto-tags`（自动打标）等破坏性任务，
  以及 ETKN 里 `implementation_status=planned` 未实现的任务。每类 ≤8 条（`news` 单条上限 8 篇）。
- **面板「任务中心」同源**：新增 `GET /api/task-catalog`，面板按同一份目录渲染 5 个分组，
  改分类只需改 `TASK_CATALOG` 一处。
- **修：markdown 泄漏到企微**。v2.9.9 把企微从 markdown 换成 text/textcard 后，
  正文里给飞书写的 `**加粗**`、`[文字](链接)` 会**字面显示**（实际踩到：菜单「立即测速」
  的结果显示成 `**⚡ 测速结果**`）。新增 `_wecom_plain()` 统一去壳，链接行也改成纯文本。
- **修：测速结果「成功也报失败」**。菜单「立即测速」的结果行读的是 `r['ms']`，
  而测速结果里的字段是 `total_ms`——取不到就一律落到「失败」分支。改成看 `ok`/`total_ms`。

**v2.9.9 变化**（2026-09-27）——修「企业微信 App 正常、微信 App 收不到」：

- **换 msgtype：`markdown` → `textcard` / `text`**。企业微信自建应用的 markdown 消息在
  **企业微信 App** 显示正常，但在**微信 App（微信插件）**一律只显示一行
  「暂不支持此消息类型，请在企业微信中查看」——微信端**只认 `text` 和 `textcard`**。
  同一接收人、只改 msgtype 的三组对照实验结论：

  | msgtype | 企业微信 App | 微信 App |
  |---|---|---|
  | `markdown` | 正常 | ❌ 显示「暂不支持此消息类型」 |
  | `text` | 正常 | ✅ 正常 |
  | `textcard` | 正常 | ✅ 正常（卡片：标题 + 描述 + 可点 URL） |

  新策略：**有标题 + 有可点 URL + 描述 ≤512 字节 → 发 `textcard` 卡片**（最接近飞书卡片）；
  **否则回落 `text`**（2048 字节，按字节裁，链接行与「推送时间」页脚永远保留，不裁字）。
  两个上限都是企微官方口径（`textcard.title` ≤128B、`textcard.description` ≤512B）。
- 面板设置页的「微信 App 收不到？」排查清单补上消息类型说明（原来的 markdown 说明已过时）。
- 版本串 v2.9.8 → v2.9.9（`/api/meta` 与启动横幅）。

**v2.9.7 变化**（2026-09-27）——通知渠道四个修补（都是实际用出来的问题）：

- **飞书补独立开关**：`feishu_enabled`（面板 → 设置 →【推送】→「飞书通知渠道」）。此前只有「推送总开关」+ 企微开关，
  想单独关飞书只能清空 Webhook 地址。现在两条通道各自独立，默认开（老配置升级后行为不变）。
- **改面板地址自动重下发企微菜单**：企微自定义菜单是「下发即固化」的，改设置里的面板公网地址**不会**自动生效，
  菜单会一直指旧地址（实际踩到：设置改成新域名，菜单里还是旧的）。现在保存设置时检测到地址变化就自动重下发，
  并在设置页新增「菜单下发结果」一行回显时间/成功失败/实际用的地址。
- **企微消息对齐飞书**：正文底部追加 `markdown` 链接行（卡片按钮 → `[文字](url)`）；
  每条消息末尾追加「推送时间 YYYY-MM-DD HH:MM:SS」灰色小字（`<font color="comment">`）。
- **修字节上限 bug**：企微 markdown `content` 官方上限是 **2048 字节**，旧代码按**字符** `[:4000]` 截断——
  一个汉字 3 字节，中文正文很容易超限被企微静默截断，而且**时间戳页脚会被截没**。
  现改为按字节裁剪，并先给页脚留位置，保证时间戳永远在。
- 设置页新增「微信 App 收不到？」排查清单（企微「微信插件」5 条前提 + 官方 20 字节限制说明）。

**v2.5.5 变化**（2026-09-18）——清空提醒三项改进 + 一键整理入口：
- **双口径**：汇总行改为「本批：任务 完成X·失败Y·取消Z ｜ 媒体 完成A·失败B」；任务口径=终态任务数，媒体口径=各终态任务 `/api/workflows/{id}/status` 的 summary.succeeded/failed 累计（与 p115 记录一致；仅终态时各拉一次，零高频新增）
- **统计范围**：上次清空→本次清空之间进入终态的整理类任务
- **批耗时**：「最后任务耗时」保留，另加「本批总耗时 xx 分钟（HH:MM 开始 → HH:MM 清空）」；批开始=批内第一个整理类任务入队时刻（首个完成任务的开始时刻近似，纯排队批次=入队时刻）
- **后台全量快照**：「当前队列」一行式含全类型（刮削/网盘/共享/追剧，复用分类队列同源数据）
- **修复**：v2.5.4 的 `prev_queued` 提前覆盖缺陷（排队历史被当轮值覆盖 → 纯排队批次清空永不触发）
- **一键整理入口**（设置页开关，默认关）：清空提醒底部附「👉 整理下一批」链接 → monitor 新端点 `/trigger/organize`：GET 显示确认页（动作说明+当前队列快照，取消为默认焦点），确认后 POST 触发 ETKN 原生「手动整理网盘文件」（与面板按钮同一接口，`organize-p115` 载荷）；一次性令牌 30 分钟有效、每次清空轮换旧令牌作废、触发即作废；忙锁防连点（429）+ 触发前复核整理队列非空则拒绝（409）；链接基址=设置页「外网面板地址」（空=内网地址）

**v2.5.5 修复两项**（2026-09-18 午后）：

**v2.5.3 变化**（2026-09-17）——整理任务静止告警 + 完成提醒：
- **静止告警**：对 running 的整理类任务（网盘整理/刮削入库/手动整理，按 display_title 前缀区分，排除共享登记/追剧刷新——其 workflow_type 同为 manual_task 按类型筛会误伤）检测「最后推进时间」；连续 N 分钟零推进推送一次（N 默认 10，可配），持续静止按重复间隔再提醒（默认 30 分钟，可配），恢复推进/任务结束自动停止
- **判据**：优先任务日志接口最后一条时间（GET /api/workflows/{id}/logs?limit=1 实测返回最新一条，新→旧）；接口失败回退 succeeded+failed+active 计数快照对比
- **大文件宽限**：任务运行超 1 小时阈值自动放宽到 30 分钟（开关默认开）。限制说明：ETKN 接口无文件大小信号（upload_total_bytes 恒 0、/items 端点 404），无法按「单文件 ≥20GB」判定，以运行时长作替代信号

## 部署（Docker / Docker Compose）

任意装了 Docker 的 Linux 或 NAS 都能跑：纯 Python 无二进制依赖，x86_64 / arm64 均可。

```bash
# 1. 克隆
git clone https://github.com/YisBoss/etkn-monitor.git
cd etkn-monitor

# 2. 准备配置（.env 已被 .gitignore 忽略，绝不会进仓库）
cp .env.example .env
vi .env            # 至少填 ETKN_BASE_URL / ETKN_USERNAME / ETKN_PASSWORD

# 3. 启动
docker compose up -d --build

# 4. 验证
curl http://127.0.0.1:8620/api/meta
```

浏览器打开 `http://<机器IP>:8620`。

> 没有 `.env` 也能启动（`env_file` 是可选项，需要 Docker Compose ≥ 2.24），
> 但连不上 ETKN —— 面板会一直显示取数失败。变量含义见 `.env.example` 和下面「配置」表。

**自动喂料（可选）**：需要把 CloudDrive 的 115 目录挂进容器——在 `.env` 里写
`CLOUD115_DIR=/你的/CloudDrive/115`。不写则该功能不可用，其余功能不受影响。

**hosts 巡检 / 自动重启（可选）**：需要容器能 SSH 到运行 ETKN 的那台机器，
在 `.env` 里配 `SSH_HOST` / `SSH_PORT` / `SSH_USER` / `SUDO_PASSWORD`。

## 通知渠道

告警支持两条通道，**可以同时开**，任一通道送达即算推送成功；两条通道**各有独立开关**
（面板 → 设置 →【推送】→「飞书通知渠道」/【企业微信】→「企业微信通知渠道」），
另有「推送总开关」作为总闸（关掉则两条都静默）：

| 通道 | 配置位置 | 说明 |
|---|---|---|
| 飞书群机器人 | 面板 → 设置 →【推送】 | 填 Incoming Webhook 地址即可，最省事；卡片带按钮行 + 底部推送时间小字 |
| 企业微信自建应用 | 面板 → 设置 →【企业微信】 | 应用消息（`textcard` 卡片 / 超长回落 `text`）+ 自定义菜单 + 文本指令（回调）；正文带链接行 + 底部推送时间小字 |

面板**页头**会显示 `📣 飞书 · 企微` 徽标（绿=有可用通道 / 红=无可用通道 / 灰=已静默），
悬停看明细；**任务统计页 →「系统状态」**里有「通知渠道」一行，含最近一次企微发送结果。
一眼就能看出「告警到底发不发得出去」。

### 企业微信自建应用接入步骤

1. 企微管理后台 → 应用管理 → 自建 → 创建应用，记下 **AgentId** 与 **Secret**；
2. 应用详情 →「接收消息」→ 设置 API 接收：
   - **URL**：`https://<你的面板公网域名>/wecom/callback`
   - **Token** / **EncodingAESKey**：随机生成后，抄到面板设置里（要一一对应）
3. 「企业可信IP」填**调用企微 API 的出口 IP**——也就是跑本容器那台机器的公网出口 IP。
   出口 IP 会漂（PPPoE / CGNAT）的话，在面板【企业微信】里填「API 代理」，
   把调用固定从某个固定 IP 的机器出去（例：`http://user:pass@1.2.3.4:7897`，
   指向一个只放行 `qyapi.weixin.qq.com:443` 的 CONNECT 代理）；
4. 面板 → 设置 →【企业微信】：填企业ID / AgentId / Secret / 接收人 / 回调 Token / EncodingAESKey
   → 打开开关 → 点「测试企业微信」；
5. 点「下发自定义菜单」，企微客户端里**重新进入应用**即可看到菜单。

菜单结构（v2.9.10）：

```
📈查状态                  ← 点击直出「今日/本周完成 + 活跃队列」
🔧运维操作
  ├ 🔍检测500   ├ ⚡立即测速   ├ 🌐重检IP
  ├ 📁整理一批   └ 🧹清理临时
📚任务中心                 ← 二级 = ETKN 工具箱的 5 个分类
  ├ 🎬媒体维护   ├ 📁115整理   ├ 📺订阅追剧
  ├ 📚媒体库     └ 🔑账号系统
      ↓ 点击分类 → 推一条图文消息（news），每条 = 该分类下一个子任务
      ↓ 点子任务 → 确认页 → 确认执行 → 触发 ETKN
```

> ⚠️ 菜单名受企微限制：**每个名字不超过 16 个字节**（UTF-8；一个汉字 3 字节、一个 emoji 4 字节），
> 超了企微直接返回 `40058` 拒收。改名字前先 `len(name.encode('utf-8'))` 数一遍。
> 面板里改完点「下发自定义菜单」即可，程序会先做本地字节数校验。
>
> ⚠️ 菜单是**下发即固化**的：改代码里的 `_WECOM_MENU` 后，必须重新点「下发自定义菜单」
> 才会生效（企微端也不会主动拉取）。结果回显在设置页「菜单下发结果」一行。
> v2.9.8 起菜单里已无动态 URL，所以改设置不再需要重下发菜单。
>
> ⚠️ 企微自定义菜单**只有两级**（一级 ≤3 个、每个一级下二级 ≤5 个，没有第三级），
> 所以「分类里再展开子任务」菜单做不到，只能靠点击分类后**推一条图文消息**来展开。

### 任务中心（ETKN 原生任务）

面板「任务中心」卡片与企微菜单「📚任务中心」是**同一批任务**（同一份 `TASK_CATALOG`，
面板经 `GET /api/task-catalog` 取用），都走 `POST /api/task-center/tasks/<key>/runs`
（服务端默认参数），触发后任务进入 ETKN 队列，可随时在 ETKN 任务中心取消。

按 ETKN 工具箱的 5 个分类组织，共 26 个任务（每类 ≤8 条，受 `news` 单条 8 篇上限约束）。
出于安全考虑走**白名单**——面板无鉴权，不透传等于给面板开了个「任意任务代理」：

- **破坏性任务一律不收**：`delete-115-shares`（删除分享入库）、`execute-duplicate-media`（执行去重）、
  `apply-auto-tags`（自动打标）、`manually-correct-organize-records`（手动重组记录）等；
- **未实现的不收**：ETKN 里 `implementation_status=planned` 的一律排除；
- 想加减任务，改 `TASK_CATALOG` 一处即可（菜单、面板、白名单都由它派生）。

企微里点分类展开的子任务链接形如
`https://<面板地址>/run-task/<task_key>?token=<进程令牌>`，落地是**确认页**而不是直接触发——
微信/企微打开链接会预取，点开即跑等于打开一条消息就把整类任务全触发。令牌是进程级的
（容器重启即轮换），只防「链接被预取/被猜到」。

### 消息格式说明（msgtype 与字节上限）

企微应用消息**不发 `markdown`**——因为**微信端（微信插件）不支持 markdown**，
会显示成「暂不支持此消息类型，请在企业微信中查看」。四种类型的实测对照（真机，只改 msgtype）：

| msgtype | 企业微信 App | 微信 App（微信插件） |
|---|---|---|
| `markdown` | 正常 | ❌「暂不支持此消息类型」 |
| `text` | 正常 | 正常，但**不渲染 markdown**（`**粗体**`、`[名字](url)` 原样露出） |
| `textcard` | 正常 | 正常（标题 + 描述 + **一个**可点 URL） |
| `news` | 正常 | 正常（第一条=标题+描述，之后每条=一行**可点名字**） |

本程序的选择：

| 条件 | msgtype | 上限（官方口径，UTF-8） |
|---|---|---|
| 有标题或有链接，且正文放得下 | `news`：第一条=标题+正文+推送时间，之后每个链接一条 | 每条 `title` ≤128 字节；第一条 `description` ≤512 字节；≤8 条 |
| 其余（正文超 512 字节 / 既无标题又无链接） | `text`（纯文本，链接行与页脚保留） | `content` ≤2048 字节 |

都按**字节**裁剪（一个汉字 3 字节），并优先保住末尾的「推送时间」页脚；
`news` 第一条的正文若与卡片标题重复（`⚠️ ETKN 告警 · X` / `✅ ETKN 整理任务已清空…`）会自动去掉。

> ⚠️ **微信端只渲染 `news` 里每条的 `title`**（只有第一条额外显示 description），
> 所以链接必须单独成条、且标题要能独立看懂——不能把关键信息只放在 description 里。
`textcard` 的正文首行若与卡片标题重复（`⚠️ ETKN 告警 · X`）会自动去掉，避免标题下再重复一遍。

> 想在企微 App 里要 markdown 的加粗/标题观感是做得到的，但那样**微信 App 就收不到**——
> 企微没有「按客户端分开发不同 msgtype」的能力，只能二选一。这里选了「两端都能看到」。

### ⚠️ 企业微信 App 收到、但**微信 App** 收不到？

这不是本程序的问题——企微「**微信插件**」是一条独立通道，默认不生效。逐条核对：

1. **微信里先关注「微信插件」**（企微管理后台 → 微信插件 → 生成二维码，用微信扫码关注）；
2. 微信 → 通讯录 → 点已关注的「微信插件」→ 右上角 → 设置 → **开启「接收企业消息」**；
3. 企微管理后台 → 微信插件 → **不要勾选**「成员使用微信插件时需要使用企业微信客户端」；
4. 企微手机端 → 左上角「≡」→ 设置 → 消息通知 → **不要勾选**「仅在企业微信中接收消息」；
5. 应用不能被停用；全员群人数超 2000 不同步到微信插件。

> 官方限制（无法绕过）：若管理端给应用设置了「**在微工作台中始终进入主页**」，
> 应用在**微信端只能收到文本消息，且长度限制 20 字节**，超过会被截断；
> 其他消息类型（含卡片）会被**转成文本**并提示用户到企业微信查看。
> 参考：企微帮助中心《如何接收微信插件消息》与《发送应用消息》文档。

## 安全

- 零密钥设计：密码只放 `.env`（600 权限），不入代码、不入仓库；Git 已忽略 `.env`。
- 测速与重试均为手动触发，无任何定时任务。
- 重试仅转发 ETKN 官方接口；ETKN 的拒绝（409 等）原样透传展示。
